# HDL Buspro для Home Assistant

[🇧🇾 Беларуская](../be/README.md) | [🇩🇪 Deutsch](../de/README.md) | [🇬🇧 English](../../README.md) | [🇪🇸 Español](../es/README.md) | [🇫🇷 Français](../fr/README.md) | [🇮🇹 Italiano](../it/README.md) | [🇳🇱 Nederlands](../nl/README.md) | [🇳🇴 Norsk](../no/README.md) | 🇷🇺 Русский | [🇺🇦 Українська](../uk/README.md)

Интеграция управляет шлюзом и физическими устройствами HDL Buspro через
интерфейс Home Assistant. Полный список моделей, сущностей и сервисов приведён
в [английской документации](../README.md).

## Установка

### HACS (рекомендуется)

1. Откройте **HACS > Интеграции**.
2. Откройте меню с тремя точками и выберите **Пользовательские репозитории**.
3. Добавьте `https://github.com/Frequencies/home_assistant_buspro` с категорией
   **Интеграция**.
4. Найдите **HDL Buspro**, откройте её и выберите **Скачать**.
5. Перезапустите Home Assistant, когда HACS предложит это.

Будущие версии можно устанавливать из **HACS > Интеграции**.
Перезапускайте Home Assistant после каждого обновления интеграции.

### Ручная установка

1. Скачайте репозиторий интеграции.
2. Скопируйте её директорию `custom_components/buspro` в
   `/config/custom_components/buspro` в Home Assistant.
3. Перезапустите Home Assistant.

## Первая настройка

### Конфигурация шлюза
1. Откройте **Настройки > Устройства и службы > Добавить интеграцию** и
   выберите **HDL Buspro**.
2. Введите хост шлюза и порты UDP. Обычный порт — `6000`.
3. Введите неиспользуемый адрес Buspro для Home Assistant в формате
   `подсеть.устройство`. По умолчанию `200.200`; он не должен принадлежать
   другому устройству Buspro.

### Добавление устройств
После завершения конфигурации шлюза:

1. Откройте **Настройки > Устройства и службы > HDL Buspro > Настройка**.
2. Нажмите **Добавить устройство** для добавления физического модуля.
3. **Выберите тип устройства** (Реле, Диммер, Занавес, Климат, Датчик и т.д.).
4. **Выберите точную модель** соответствующую вашему оборудованию.
5. **Введите адрес Buspro** в формате `подсеть.устройство` (например, `1.5`).
6. **Введите имя устройства** (например, "Свет гостиной").
7. **Назовите каждый канал** — оставьте пустым, чтобы отключить канал.
8. Нажмите **Сохранить**.

Home Assistant автоматически группирует сущности по физическому модулю в реестре устройств.

**Подробные примеры конфигурации UI и YAML для всех типов устройств см. [../en/DEVICE_EXAMPLES.md](../en/DEVICE_EXAMPLES.md).**

### Редактирование устройств

Чтобы изменить существующее устройство, откройте **Настройка > Редактировать
устройство**. Вы можете:
- Переименовать устройство
- Переименовать, включить или отключить отдельные каналы
- Изменить модель (может изменить количество каналов)
- Полностью удалить устройство

Управляемые интерфейсом устройства поддерживают полное редактирование.
Устаревшие устройства YAML могут предоставлять элементы управления
именованием реестра, но их конфигурация протокола всё ещё должна
изменяться в YAML. Перезапустите Home Assistant после изменений YAML.

### Пример: Добавление 4-канального модуля реле

1. Модель: `HDL-MR0410.431` (4 реле-канала)
2. Адрес Buspro: `1.10`
3. Имя устройства: "Реле комнаты"
4. Имена каналов:
   - Канал 1: "Потолочный свет"
   - Канал 2: "Настенная лампа"
   - Канал 3: "" (отключено)
   - Канал 4: "Вентилятор"

После сохранения Home Assistant создаёт:
- `light.room_relays_ceiling_light`
- `light.room_relays_wall_lamp`
- `switch.room_relays_fan`

Полные примеры UI и YAML для всех типов устройств см. **[../en/DEVICE_EXAMPLES.md](../en/DEVICE_EXAMPLES.md)**.

## Критические изменения в версии 2.2.0

- Адреса, имена, количество устройств и назначения каналов больше не
  встроены в интеграцию. Они сохраняются в опциях записи конфигурации.
- Точная модель определяет физическое количество каналов и создаваемые
  сущности.
- Канал без имени отключен и не создается.
- Адрес Buspro Home Assistant переносится по умолчанию в `200.200`. Этот
  адрес должен быть свободен в сети.
- События панели теперь декодируются как `channel_on`, `channel_off`,
  `channel_level`, `scene` и события универсального переключателя.
- Встроенный конструктор `Buspro` теперь требует `client_address`.

## Обновление

1. Перезапустите Home Assistant после замены компонента.
2. Откройте **Настройки > Устройства и службы > HDL Buspro > Настройка**.
3. Проверьте шлюз, порты UDP и неиспользуемый адрес Buspro для Home Assistant.
4. Выберите точную модель для каждого устройства и проверьте имена каналов.
5. Проверьте автоматизации, использующие события панели.
6. Удалите или закомментируйте старые сущности YAML только после проверки
   их замен, управляемых интерфейсом.

Не конфигурируйте один и тот же физический канал одновременно в YAML и через
интерфейс. Это создаст дублирующиеся сущности и подписки на протокол.

## YAML-конфигурация (устаревшая)

Конфигурация устройств YAML полностью поддерживается вместе с управлением
шлюзом через запись конфигурации. Вы можете определять светильники, занавесы,
переключатели, вентиляторы, климат-контроль, датчики и бинарные датчики
через YAML, пока шлюз управляется интерфейсом интеграции.

**Примечание**: Новые устройства должны использовать интерфейс
**Настройка > Добавить устройство** вместо YAML, так как он обеспечивает
группировку устройств, управляемые моделью возможности и управление
состоянием канала. YAML рекомендуется для:
- Устройств с нестандартными или устаревшими профилями
- Миграции из старых интеграций Buspro
- Сложной автоматизации или шаблонов датчиков

### Пример синтаксиса YAML

Добавьте в ваш `configuration.yaml`:

```yaml
light:
  - platform: buspro
    devices:
      "1.5.1":
        name: "Потолочный свет"
        dimmable: true
      "1.5.2":
        name: "Настенная лампа"
        dimmable: false

cover:
  - platform: buspro
    devices:
      "2.10.1":
        name: "Занавес гостиной"
        running_time: 45

climate:
  - platform: buspro
    devices:
      "3.1":
        name: "Климат спальни"
        profile: "ac"
```

### Конфигурация платформы

Каждая платформа (`light`, `cover`, `fan`, `climate`, `sensor`, `binary_sensor`,
`switch`) принимает:

| Ключ | Тип | Описание |
| --- | --- | --- |
| `devices` | dict | Обязательно. Отображение адресов Buspro на конфигурации устройств. |
| `running_time` | int | Время перехода по умолчанию в секундах (0 = без перехода). Переопределяется за устройство. |
| `ack_retry_enabled` | bool | Повторить отправку без ACK (стандарт платформы; переопределяется за устройство). |

Каждый ключ устройства является **адресом Buspro** в формате:
- **Свет, занавес, вентилятор, переключатель**: `подсеть.устройство.канал` (например, `1.5.2`)
- **Климат, датчик, бинарный датчик**: `подсеть.устройство` (например, `3.1`)

Каждая конфигурация устройства поддерживает:
- `name` (обязательно): Имя для отображения
- `running_time`, `dimmable`, `ack_retry_enabled` (специфично для платформы, опционально)
- `profile` (опционально, для датчиков климата — например, `"ac"`, `"floor_heating"`)
- `object_id` (опционально): Slug ID сущности
- `unique_id` (опционально): Для ручного управления реестром сущностей

## Настройка шлюза

Добавьте **HDL Buspro** из **Параметры > Устройства и службы** и настройте:

- **Хост**: имя хоста или IPv4-адрес шлюза HDL.
- **Порт**: основной порт UDP, обычно `6000`.
- **Порты отправки/приёма UDP**: меняйте только для нестандартного шлюза.
- **Адрес Buspro Home Assistant**: неиспользуемый идентификатор `subnet.device`, такой как миграционный по умолчанию `200.200`.

UDP не имеет рукопожатия соединения. Настройка проверяет разрешение адреса, маршрутизацию и создание локального приёмного сокета без предположения о наличии устройства по жесткозакодированному адресу Buspro.

## Управление устройствами

Откройте **Настройка** в интеграции и выберите:

- **Параметры шлюза** для обновления сетевых параметров и идентификатора клиента.
- **Добавить устройство** для выбора типа устройства, модели, адреса Buspro и имён каналов или возможностей.
- **Редактировать устройство** для переименования каналов, включения или отключения каналов, удаления управляемого UI устройства или исправления модели существующей записи реестра.

Физические адреса отображаются в Home Assistant как серийный номер устройства. Сущности, принадлежащие одному физическому модулю, привязаны к одной записи реестра устройств.

## Помощник по обслуживанию каталога

Чтобы сравнить каталог интеграции с поддерживаемым официальным списком моделей HDL, запустите:

```bash
python3 custom_components/buspro/tools/check_catalog_models.py
```

Помощник читает `custom_components/buspro/devices/official_models.json` и выводит:

- официальные модели, отсутствующие в `DEVICE_CATALOG`
- модели каталога, отсутствующие в официальном списке
- виртуальные универсальные модели, только для интеграции

Используйте строгий режим для проверок CI-стиля (выход с ненулевым кодом, когда в каталоге отсутствуют официальные модели):

```bash
python3 custom_components/buspro/tools/check_catalog_models.py --strict
```

## Поведение сущностей

### Реле

Один общий координатор запрашивает статус реле один раз для каждого физического модуля и распределяет ответ всем сущностям активного канала. Отключённые каналы не подписываются и не запрашивают шину.

### Панели

Известные кнопочные панели создают одну сущность `event` для каждой физической кнопки, событие `Action` и датчик `Last action`. Сущности события кнопки UI представляют полученные физические телеграммы кнопок Buspro; они не имитируют аппаратное нажатие.

### Диммеры

Поддерживаемые диммеры могут предоставлять подключение, максимальную яркость для каждого канала, тип нагрузки и минимальную яркость, сообщённую протоколом. `Not reported` означает, что устройство вернуло дозорный протокол вместо используемого значения.

### Контроллер логики

`HDL-MCLog.431` предоставляет доступ только для чтения к подключению, версии прошивки, последнему просмотру и сущностям события логики. Некоторая прошивка не отвечает на стандартный запрос прошивки; в этом случае сущность прошивки остаётся недоступной. Логические блоки не доступны для записи, потому что их изменение может перезаписать программирование контроллера.

## Сервисы

- `buspro.activate_scene`
- `buspro.set_universal_switch`
- `buspro.send_message`

`buspro.send_message` отправляет сырую команду протокола и должна использоваться только с проверенным HDL-кодом операции и полезной нагрузкой.

### Запуск тестовых наборов

Из директории конфигурации Home Assistant:

```bash
# Запустить все тесты протокола (19 тестов)
python3 -m unittest discover -s custom_components/buspro/tests/buspro_protocol -v

# Запустить все тесты интеграции (18 тестов)
python3 -m unittest discover -s custom_components/buspro/tests/buspro_integration -v

# Или запустить отдельные файлы тестов
python3 custom_components/buspro/tests/buspro_protocol/test_sensor_protocol.py
python3 custom_components/buspro/tests/buspro_protocol/test_relay_coordinator.py
python3 custom_components/buspro/tests/buspro_protocol/test_logic_controller_protocol.py
python3 custom_components/buspro/tests/buspro_protocol/test_config_isolation.py
python3 custom_components/buspro/tests/buspro_protocol/test_device_lifecycle.py
python3 custom_components/buspro/tests/buspro_integration/test_device_catalog.py
python3 custom_components/buspro/tests/buspro_integration/test_managed_device_logic.py
python3 custom_components/buspro/tests/buspro_integration/test_model_notes_logging.py
```

Тесты протокола охватывают анализ телеграмм, координацию устройств и
безопасность основных задач/обратных вызовов. Тесты интеграции охватывают
каталог устройств, логику управляемых устройств, нормализацию YAML и
отслеживание поддержки моделей.
