# HDL Buspro для Home Assistant

[English](../README.md) | **Русский**

Интеграция управляет шлюзом и физическими устройствами HDL Buspro через
интерфейс Home Assistant. Полный список моделей, сущностей и сервисов приведён
в [английской документации](../README.md).

## Установка

### HACS (рекомендуется)

1. Откройте **HACS > Интеграции**.
2. Откройте меню с тремя точками и выберите **Пользовательские репозитории**.
3. Добавьте `https://github.com/Frequencies/home_assistant_buspro` с категорией
   **Интеграция**.
4. Найдите **HDL Buspro**, откройте его и нажмите **Скачать**.
5. Перезапустите Home Assistant, когда HACS предложит это сделать.

Последующие версии можно устанавливать через **HACS > Интеграции**.
Перезапускайте Home Assistant после каждого обновления интеграции.

### Ручная установка

1. Скачайте репозиторий интеграции.
2. Скопируйте его каталог `custom_components/buspro` в
   `/config/custom_components/buspro` в Home Assistant.
3. Перезапустите Home Assistant.

## Первая настройка

1. Откройте **Настройки > Устройства и службы > Добавить интеграцию** и
   выберите **HDL Buspro**.
2. Укажите адрес шлюза и UDP-порты. Стандартный порт — `6000`.
3. Укажите свободный адрес Home Assistant в Buspro в формате
   `подсеть.устройство`. Адрес `200.200` используется по умолчанию и не должен
   принадлежать другому устройству.
4. Откройте **Настроить > Добавить устройство**, выберите тип и точную модель,
   затем укажите физический Buspro-адрес и имя.
5. Задайте имена нужным каналам или возможностям. Пустое имя оставляет канал
   отключённым, и его сущность не создаётся.

Для известной модели интеграция использует фиксированное количество каналов
или список возможностей из каталога. Для универсального профиля пользователь
задаёт количество каналов в пределах поддерживаемого лимита. После сохранения
запись конфигурации перезагружается, а сущности группируются под одним
физическим устройством.

Для изменения откройте **Настроить > Изменить устройство**. У созданных через
UI устройств можно изменить модель, имя и каналы либо удалить устройство.
Протокольные параметры старых YAML-устройств по-прежнему изменяются в YAML;
после изменения перезапустите Home Assistant.

## Критические изменения в 2.2.0

- Адреса, имена, количество устройств и назначения каналов больше не встроены
  в интеграцию. Они хранятся в параметрах записи конфигурации.
- Точная модель определяет физическое количество каналов и создаваемые сущности.
- Канал с пустым именем отключён и не создаётся.
- Адрес Home Assistant в сети Buspro по умолчанию переносится на `200.200`. Он
  должен быть свободен в вашей сети.
- События панелей теперь декодируются как `channel_on`, `channel_off`,
  `channel_level`, `scene` и события универсального переключателя.
- Конструктор встроенной библиотеки `Buspro` теперь требует `client_address`.

## Обновление

1. Перезапустите Home Assistant после замены компонента.
2. Откройте **Настройки > Устройства и службы > HDL Buspro > Настроить**.
3. Проверьте шлюз, UDP-порты и свободный Buspro-адрес Home Assistant.
4. Выберите точную модель каждого устройства и проверьте имена каналов.
5. Проверьте автоматизации, использующие события панелей.
6. Удаляйте или комментируйте старые YAML-сущности только после проверки их
   замен, созданных через UI.

Не описывайте один физический канал одновременно в YAML и через UI: это
создаёт дубли сущностей и подписок на протокол.

## Проверка каталога и тесты

Чтобы сравнить каталог моделей с поддерживаемым официальным списком HDL:

```bash
python3 custom_components/buspro/tools/check_catalog_models.py
python3 custom_components/buspro/tools/check_catalog_models.py --strict
```

Для legacy YAML-устройств интеграция теперь нормализует отсутствующие профили
по метаданным модели. Неизвестные модели или некорректные профили
логируются как предупреждение и переводятся на `sensor_status`.

Запуск целевых тестов интеграции:

```bash
python3 -m unittest discover -s custom_components/buspro/tests/buspro_protocol -p 'test_*.py'
python3 -m unittest discover -s custom_components/buspro/tests/buspro_integration -p 'test_*.py'
```
