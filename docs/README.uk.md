# HDL Buspro для Home Assistant

[English](../README.md) | **Українська**

Інтеграція керує шлюзом і фізичними пристроями HDL Buspro через інтерфейс
Home Assistant. Повний перелік моделей, сутностей і сервісів наведено в
[англійській документації](../README.md).

## Встановлення

### HACS (рекомендовано)

1. Відкрийте **HACS > Інтеграції**.
2. Відкрийте меню з трьома крапками та виберіть **Користувацькі репозиторії**.
3. Додайте `https://github.com/Frequencies/home_assistant_buspro` із категорією
   **Інтеграція**.
4. Знайдіть **HDL Buspro**, відкрийте його та натисніть **Завантажити**.
5. Перезапустіть Home Assistant, коли HACS запропонує це зробити.

Наступні версії можна встановлювати через **HACS > Інтеграції**. Перезапускайте
Home Assistant після кожного оновлення інтеграції.

### Ручне встановлення

1. Завантажте репозиторій інтеграції.
2. Скопіюйте його каталог `custom_components/buspro` до
   `/config/custom_components/buspro` у Home Assistant.
3. Перезапустіть Home Assistant.

## Перше налаштування

1. Відкрийте **Налаштування > Пристрої та служби > Додати інтеграцію** та
   виберіть **HDL Buspro**.
2. Укажіть адресу шлюзу та UDP-порти. Звичайний порт — `6000`.
3. Укажіть вільну адресу Home Assistant у Buspro у форматі
   `підмережа.пристрій`. Адреса `200.200` використовується типово й не повинна
   належати іншому пристрою.
4. Відкрийте **Налаштувати > Додати пристрій**, виберіть тип і точну модель,
   потім укажіть фізичну Buspro-адресу та назву.
5. Задайте назви потрібним каналам або можливостям. Порожня назва залишає канал
   вимкненим, і його сутність не створюється.

Для відомої моделі інтеграція використовує фіксовану кількість каналів або
перелік можливостей із каталогу. Для універсального профілю користувач задає
кількість каналів у межах підтримуваного ліміту. Після збереження запис
конфігурації перезавантажується, а сутності групуються під одним фізичним
пристроєм.

Для внесення змін відкрийте **Налаштувати > Змінити пристрій**. Для створених
через UI пристроїв можна змінити модель, назву й канали або видалити пристрій.
Протокольні параметри старих YAML-пристроїв і надалі змінюються в YAML; після
зміни перезапустіть Home Assistant.

## Критичні зміни у 2.2.0

- Адреси, назви, кількість пристроїв і призначення каналів більше не вбудовані
  в інтеграцію. Вони зберігаються в параметрах запису конфігурації.
- Точна модель визначає фізичну кількість каналів і створювані сутності.
- Канал із порожньою назвою вимкнений і не створюється.
- Адреса Home Assistant у мережі Buspro типово переноситься на `200.200`. Вона
  має бути вільною у вашій мережі.
- Події панелей тепер декодуються як `channel_on`, `channel_off`,
  `channel_level`, `scene` і події універсального перемикача.
- Конструктор вбудованої бібліотеки `Buspro` тепер вимагає `client_address`.

## Оновлення

1. Перезапустіть Home Assistant після заміни компонента.
2. Відкрийте **Налаштування > Пристрої та служби > HDL Buspro > Налаштувати**.
3. Перевірте шлюз, UDP-порти та вільну Buspro-адресу Home Assistant.
4. Виберіть точну модель кожного пристрою та перевірте назви каналів.
5. Перевірте автоматизації, що використовують події панелей.
6. Видаляйте або коментуйте старі YAML-сутності лише після перевірки їх замін,
   створених через UI.

Не описуйте один фізичний канал одночасно в YAML і через UI: це створює
дублікати сутностей і підписок на протокол.

## Перевірка каталогу і тести

Щоб порівняти каталог моделей із підтримуваним офіційним списком HDL:

```bash
python3 custom_components/buspro/tools/check_catalog_models.py
python3 custom_components/buspro/tools/check_catalog_models.py --strict
```

Для legacy YAML-пристроїв інтеграція тепер нормалізує відсутні профілі за
метаданими моделі. Невідомі моделі або некоректні профілі логуються як
попередження і переводяться на `sensor_status`.

Запуск цільових тестів інтеграції:

```bash
python3 -m unittest discover -s custom_components/buspro/tests/buspro_protocol -p 'test_*.py'
python3 -m unittest discover -s custom_components/buspro/tests/buspro_integration -p 'test_*.py'
```
